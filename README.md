# Telegram Reader Showcase

Публичный обезличенный срез личного проекта Михаила Жарова (MostWanted), подготовленный 22 октября 2026 года. Основа — актуальная ветка Telegram Reader MCP, развивавшаяся в октябре 2026 года. Это пример реализованной интеграции Telegram и ИИ-клиента, а не свидетельство продажи или клиентского внедрения.

Сохранены рабочие модули и автоматические тесты. Данные аккаунта, история переписок, конфигурация сервера, сессии Telegram и прежняя история Git в этот срез не входят. Идентификаторы в тестах синтетические. При первичной настройке владелец вводит свой числовой GitHub ID; заранее выбранного владельца в публичной версии нет.

## Реализованные возможности

| Инструмент | Результат |
| --- | --- |
| `list_chats` | Поиск разрешённых чатов по названию с пагинацией |
| `get_chat_history` | История за указанный период |
| `search_messages` | Поиск сообщений в чате или разрешённом аккаунте |
| `get_message_context` | Сообщение и его настоящие соседи |
| `get_message_text` | Чтение длинного текста по частям |
| `get_media` | Метаданные и временная защищённая ссылка на оригинал до 50 МиБ |
| `read_document` | Извлечение текста PDF, DOCX, XLS/XLSX, PPTX, TXT/CSV/TSV по частям |
| `transcribe_voice` | Запрос встроенной расшифровки выбранного голосового в Telegram |
| `get_profile` | Идентификатор подключённого аккаунта без телефона |

Сервер не отправляет и не удаляет сообщения, не ставит реакции и отметки прочтения. Расшифровка инициирует обработку в Telegram, поэтому этот инструмент помечен недеструктивным, но не read-only. Она зависит от Premium или доступной квоты Telegram; отдельная модель и платный API для неё не используются.

## Архитектура

- `telegram_reader/reader.py`: адаптер Telethon, ограничения чатов, история, поиск и контекст.
- `telegram_reader/server.py`: MCP-инструменты, OAuth через GitHub и проверка числового ID владельца.
- `telegram_reader/media.py`: потоковая загрузка оригиналов, временные разрешения, срок хранения и очистка.
- `telegram_reader/documents.py` и `document_worker.py`: разбор документов в отдельном процессе с ограничениями ресурсов.
- `tests/`: синтетические проверки прав, пагинации, передачи файлов, парсеров и расшифровки.

Оригиналы загружаются по запросу во временный закрытый каталог, до двух файлов на пять минут. Частичные загрузки очищаются при ошибке. При скачивании по временной ссылке повторно проверяются OAuth, доступ к чату и неизменность вложения. Ссылку нельзя передавать другим людям: она содержит временный секрет доступа.

Документы не передаются целиком в MCP как base64. Инструмент возвращает текст частями с указателями продолжения и SHA-256 исходного файла. Это не OCR: изображения, визуальное оформление и вложенные объекты не извлекаются. Архивы, исполняемые файлы и старые DOC/PPT не анализируются. Для TXT/CSV/TSV также действует ограничение размера ответа.

## Воспроизводимая проверка без аккаунта Telegram

Нужен Python 3.12–3.14. В корне проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[test]'
python -m pytest -q
python -m compileall -q telegram_reader
bash -n scripts/build.sh scripts/update.sh
```

Тесты используют искусственные данные и подменённый Telegram-клиент. Тестовые ID, ключи и токены не дают доступа к реальному аккаунту. Проверяются, в частности, оригиналы 5 000 000 байт, 25 МиБ и ровно 50 МиБ, отказ при превышении лимита, SHA-256, небольшой размер MCP-ответа, отмена запроса, истечение разрешений, XML entities и порядок слайдов.

22.10.2026 для исходной актуальной версии локально прошли **84 теста**. Для этого обезличенного среза также прошли **84 теста** на macOS с Python 3.12, проверка компиляции модулей и синтаксиса shell-скриптов. Это не проверка живого production-подключения и не утверждение о совместимости с любым ИИ-клиентом.

## Самостоятельная настройка

Для реального подключения нужны собственные Telegram API credentials, отдельная пользовательская сессия, GitHub OAuth App, числовой GitHub ID владельца и HTTPS-домен. Конфигурация создаётся интерактивно:

```bash
READER_CONFIG="$PWD/config/config.json" READER_DATA="$PWD/data" python -m telegram_reader init
READER_CONFIG="$PWD/config/config.json" READER_DATA="$PWD/data" python -m telegram_reader login
```

Коды, телефон и секреты вводятся только в собственном доверенном терминале. `init` сохраняет конфигурацию с правами 600; `login` привязывает собственный Telegram. Команды не нужны для unit-тестов. Доступ к чатам выбирается владельцем; сервисные чаты с кодами входа исключены.

Для контейнерного запуска предусмотрены `Dockerfile`, `compose.yaml` и пример Caddy. `.env.example` содержит только пример домена. Перед запуском оператор настраивает собственные HTTPS и OAuth, проверяет свободные порты и исключает временный media-cache из резервных копий. Настоящий MCP URL имеет вид `https://reader.example.com/mcp`, где example-домен заменяется принадлежащим оператору адресом. HTTP-порт не следует публиковать в интернет напрямую.

Живую проверку проводят на собственном несекретном тестовом чате и специально созданном тестовом файле. `/healthz` подтверждает только работу HTTP-процесса. Нельзя считать связь с Telegram доказанной по одному healthcheck или unit-тестам.
